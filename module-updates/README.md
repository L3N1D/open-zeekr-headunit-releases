# Профили компонентов Open Headunit

Во вкладке обновлений пять компонентов. Встроенная ревизия каждого — 1. Профиль меняет только перечисленные параметры. Изменения кода, новые параметры и изменения формата требуют выпуска APK. HUD Map обновляется отдельно.

| Компонент | Параметр | Единица |
| --- | --- | --- |
| android-auto | watchdogPollMs | интервал проверки проекции в мс |
| carplay | firstTcpTimeoutMs | время ожидания первого TCP-подключения iPhone в мс |
| zeekr-integration | artQuality | качество JPEG новых обложек от 70 до 95 |
| ui | cardEnterMs | длительность открытия карточки в мс |
| autokit | discoveryPollMs | интервал поиска донгла в мс |

## Выпуск профиля

1. Скопировать последний JSON нужного компонента в той же папке. Увеличить номер в имени файла и в поле revision. Ранее опубликованные файлы сохранять без изменений.
2. Указать совместимые versionCode приложения в minCore и maxCore, изменить параметр и описать изменение в notes.
3. Из корня проекта выполнить `python3 tools/module-updates/catalog.py`. Закрытый ключ читается по переменной MODULE_SIGNING_KEY или из ~/.config/zeekr-module-updates/signing.pem. Сохранить резервную копию ключа в защищённом месте отдельно от проекта.
4. Опубликовать новые пакеты и stable.json одним коммитом в ветке main репозитория open-zeekr-headunit-releases. В каталог попадает старшая ревизия каждого компонента. Чтобы вернуть прежнее значение, выпустить следующую ревизию с этим значением.

Приложение проверяет каталог при запуске, если включена проверка обновлений, и при ручной проверке во вкладке обновлений. Оно загружает совместимые профили по идентификатору и номеру ревизии. Приложение сначала проверяет подпись и структуру каталога. Затем каждый профиль проверяется и сохраняется отдельно. Сбой загрузки одного профиля сохраняет его прежнюю версию и позволяет обновить остальные. Новые параметры вступают в силу при следующем запуске процесса приложения.
