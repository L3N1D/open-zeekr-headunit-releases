# Обновление модулей Open Headunit

Код модулей лежит в `src/<модуль>/policy.wat`. Для работы нужен компилятор `wat2wasm` в PATH или переменная WAT2WASM с путём к нему.

```sh
python3 code-modules/publish.py --check
python3 code-modules/publish.py
```

Первая команда показывает, какие пакеты изменились. Вторая собирает их и присваивает каждому следующий номер. Если два модуля поменялись одновременно, они попадают в один подписанный каталог. Повторный запуск с теми же исходниками сохраняет номера и подпись. Для подписи используется MODULE_SIGNING_KEY или локальный ключ, настроенный для этого проекта.

После тестирования в репозиторий выпуска загружаются изменённые `code-modules/packages/<id>/<номер>.wasm` и `code-modules/stable-v5.json` одним коммитом. Команда подготовки сама ничего не публикует. Прежние каталоги и файлы сохраняются по исходным адресам для старых версий приложения.

| Модуль | Код в пакете |
| --- | --- |
| Android Auto | Выбор типа автомобиля, повторы запроса версии, распознавание ответов, различение ошибки чтения и тайм-аута, причина неудачного согласования версии |
| CarPlay | Пропорции изображения, высота карточек для объявления дисплеев, команды музыкального виджета, выбор запуска или перезапуска беспроводного сеанса |
| Интеграция Zeekr | Активация медиасессии, передача метаданных, обработка команд воспроизведения от штатного музыкального виджета |
| Интерфейс | Определение перехода между окнами и длительность затемнения, расчёт доступного места и высоты ряда виджетов на главном экране |
| AutoKit | Плотность изображения, порядок открытия USB-сеанса, маршрутизация звука и выбор формата PCM |

APK включает ревизии из подписанного каталога. При сборке проверяются подпись и содержимое каждого пакета. При включённой автоматической проверке приложение скачивает обновления при открытии главного экрана, проверяет их и применяет при следующем запуске процесса. Ошибка одного пакета позволяет продолжить обновление остальных. Во время действующей проекции используется прежний набор функций.

Формат 5 добавляет в пакеты Android Auto, CarPlay и AutoKit функции управления транспортом. При смене формата интерфейса требуется однократное обновление базового APK. Последующие изменения этих программ доставляются в подписанном пакете конкретного модуля.

| Экспорт | Что выполняет |
| --- | --- |
| `openTransport(path, position)` | Выбирает порядок подготовки TCP-соединения (для AutoKit также USB). Захват устройства или соединение с выбранным адресом выполняется после проверки шагов. |
| `usbRetry(failedAttempts)` | Возвращает паузу до повторного открытия USB-устройства в миллисекундах. Ноль завершает попытки. Встроенные версии сохраняют три попытки для Android Auto и одну для iPhone и AutoKit. |
| `transfer(mode, remaining, transferred)` | Определяет объём следующего чтения или записи и продолжение после частичного обмена. Полная запись сохраняет все байты, промежуточные USB-блоки учитывают размер пакета конечной точки. USBMUX-кадр отправляется целиком. |

В Android Auto это применяется к TCP, стандартному USB и libusb. В CarPlay — к открытию iPhone, очередям чтения USBMUX и NCM, TCP-проверке Bonjour и каналам управления и событий AirPlay. В AutoKit — к USB и TCP-мосту. Запрос разрешения, дескрипторы, USB/JNI, шифрование, драйверы, декодирование и низкоуровневые механизмы обнаружения остаются в APK. Модули не получают произвольные адреса, дескрипторы или содержимое потока.
